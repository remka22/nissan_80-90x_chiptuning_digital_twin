======================================================================
  ПОПРАВКА ПЦН ИЗ ЛОГА — как пользоваться
======================================================================

ЧТО ДЕЛАЕТ
  Берёт лог поездки (.csv) и исходную таблицу ПЦН (.cte, "Поправка ЦН по
  дросселю") и считает поправку наполнения по широкополоснику.
  Результат складывает в НОВУЮ папку с датой-временем:
        результат 2026-07-14_13-05-12 (kgbc)/
  В этой папке лежат:
     - копия лога и копия исходного .cte (чтобы потом было ясно, из чего считалось);
     - отчёт .txt  — коэффициенты, число точек, сверка "тот ли cte";
     - .cte с УЖЕ применённой поправкой — готов к заливке.

ЧТО НУЖНО
  Только Python 3 (библиотеки ставить не надо).
    Windows: поставить с python.org, при установке галка "Add Python to PATH".
    macOS  : обычно уже есть; проверить в Терминале:  python3 --version


----------------------------------------------------------------------
  WINDOWS
----------------------------------------------------------------------
  Способ 1 (с окном выбора файлов):
     - двойной клик по  "Поправка (Windows).bat"
     - откроются два окна: выбрать ЛОГ (.csv), затем исходный .cte
     - готово, появится папка "результат ...".

  Способ 2 (без окон):
     - положить в ЭТУ папку ОДИН лог .csv и ОДИН исходный .cte
     - двойной клик по "Поправка (Windows).bat" — файлы возьмёт сам.

  Если "python" не найден — батник сам пробует "py".

----------------------------------------------------------------------
  macOS
----------------------------------------------------------------------
  - двойной клик по  "Поправка (Mac).command"
    (первый раз macOS может ругнуться — правой кнопкой -> Открыть -> Открыть)
  - если в папке нет ровно одного .csv и .cte — откроется окно выбора.

  Или в Терминале, из этой папки:
     python3 поправка_ПЦН.py
     python3 поправка_ПЦН.py <лог.csv> <исходник.cte>        (явные пути)
     python3 поправка_ПЦН.py <лог.csv> <исходник.cte> --cte  (другой метод, см.ниже)


----------------------------------------------------------------------
  ДВА МЕТОДА РАСЧЁТА
----------------------------------------------------------------------
  По умолчанию — kgbc. Переключение флагом: --kgbc или --cte.

  kgbc  (рекомендую):
        новая = КОЭФ_ИЗ_ЛОГА (KGBC) * поправка.
        Берём коэффициент, который РЕАЛЬНО крутился в момент лога, поэтому
        результат НЕ зависит от того, верные ли числа во входном .cte.
        Входной .cte тут только "холст": из него берутся ячейки, которых в
        логе не было, и столбцы выше 6000 об.

  cte:
        новая = ЗНАЧЕНИЕ_ВХОДНОГО_CTE * поправка.
        Классика. Верна только если входной .cte — именно тот, на котором
        снят лог (см. блок "СВЕРКА" в отчёте).


----------------------------------------------------------------------
  КАК ЧИТАТЬ ОТЧЁТ .txt
----------------------------------------------------------------------
  Шапка: метод, сколько точек использовано/отброшено, изменено ячеек.

  Блок "СВЕРКА: тот ли входной cte, что крутился в логе":
     - сравнивает входной .cte с реальным коэффициентом из лога (KGBC);
     - пишет, в скольких ячейках совпало / разошлось (с допуском) и где;
     - это ПРОСТО КОНСТАТАЦИЯ, не ошибка. Для метода kgbc расхождение на
       результат не влияет; для метода cte много расхождений = считаешь на
       неверной базе, тогда лучше метод kgbc.

  Таблицы (обороты по горизонтали, дроссель по вертикали):
     ФАКТОР ПОПРАВКИ  — во сколько раз правим (AFR_WBL/AFR):
                        <1 = было богато -> урезали; >1 = было бедно -> подняли.
                        "." = данных нет;  "~" = точек мало, в .cte НЕ применено.
     НОВЫЙ КОЭФ       — что записано в .cte для изменённых ячеек.
     КОЛИЧЕСТВО ТОЧЕК — сколько устоявшихся замеров попало в ячейку.


----------------------------------------------------------------------
  ЧТО ОТСЕИВАЕТСЯ (чтобы поправка была честной)
----------------------------------------------------------------------
    - неустоявшийся режим (резкий газ/обороты): |ΔRPM|<100, |ΔTHR|<2;
    - замкнутый цикл по лямбде (COEFF != 1) — берём только открытый;
    - активное ускорительное обогащение/обеднение (DGTC_RICH/LEAN) —
      это переходный впрыск, к базовой ПЦН отношения не имеет;
    - ячейки, где набралось меньше минимума точек (по умолчанию 4).


----------------------------------------------------------------------
  НАСТРОЙКИ (если надо строже/мягче)
----------------------------------------------------------------------
  Открыть поправка_ПЦН.py, вверху:
    METHOD     = 'kgbc'  метод по умолчанию ('kgbc' или 'cte')
    MATCH_TOL  = 0.02   допуск сверки "тот ли cte"
    MIN_POINTS = 4      минимум точек на ячейку
    DRPM_MAX   = 100    окно устоявшегося по оборотам
    DTHR_MAX   = 2      окно устоявшегося по дросселю
    CLAMP_LO/HI= 0.60 / 1.60   пределы поправки (защита от мусора)
    COEFF_TOL  = 0.05   допуск на COEFF около 1
    DGTC_MAX   = 0.1    порог отсева ускорительного обогащения


----------------------------------------------------------------------
  ВАЖНО
----------------------------------------------------------------------
  - Лог должен быть с рабочим широкополосником (колонка AFR_WBL) и в
    открытом цикле (лямбда-коррекция выкл), иначе поправка неверна.
  - Исходный .cte — именно "Поправка ЦН по дросселю" [454C2B1D], 32x16.
    Столбцы выше 6000 об скрипт не трогает — переносит как есть.
  - Один запуск = один лог. Для разных логов запускать по очереди —
    каждый создаст свою папку "результат ...".
======================================================================
