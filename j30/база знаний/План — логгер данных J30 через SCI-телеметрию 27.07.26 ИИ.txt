ПЛАН: ЛОГГЕР ДАННЫХ J30 ЧЕРЕЗ SCI-ТЕЛЕМЕТРИЮ (ПАТЧ ПРОШИВКИ)
Разбор по дизасму/бинарю 27.07.26

ЦЕЛЬ
----
Снимать живые данные с работающего ЭБУ на ходу (RPM, нагрузка, впрыск и т.д.),
минимумом проводов, проецировать на дамп. Метод — пайка к ногам процессора
HD6303Y, БЕЗ цифрового двойника, БЕЗ Consult, БЕЗ логического анализатора шины.


================================================================================
ЧАСТЬ 1. ПОЧЕМУ НЕ ЗАВОДСКОЙ SCI-ЗАГРУЗЧИК (закрытый вопрос)
================================================================================
Идея «пара проводов через заводской бэкдор» — НЕ РАБОТАЕТ для живого лога.
Оттрассировано до конца:

  - Reset (ae17) обнуляет $0040..$013F -> флаг бэкдора $40.7 после старта = 0,
    загрузчик спит.
  - Весь бэкдор заперт за $40.7:
        ad88: TIM #0x80,$0040 ; BEQ ada9 (чист -> просто RTS)
        adae: TIM #0x80,$0040 ; и сам RX-обработчик проверяет тот же флаг
  - $40.7 взводит ЕДИНСТВЕННАЯ команда b438: STAA $0040 (=0xA0), путь до неё
    жёстко заперт (вход b39c, зовётся из b0ff каждый цикл):
        b39c: нужен взведённый $40.5
        b3aa: RPM ($140A) == 0        <- ДВИГАТЕЛЬ ДОЛЖЕН СТОЯТЬ
        b3d4: $40.7 ещё не взведён    <- один раз за сессию
        b438: STAA $0040 = 0xA0       <- тут взводится
  - $40.5 (условие входа) взводится (9b05) только после того, как мотор
    поработал ($1407 >= 125 И $15.7 И $17.1 держатся ~100 циклов).

ВЫВОД: бэкдор вооружается ТОЛЬКО на заглушённом (после прогрева) моторе. Плюс
вход в загруженный код — это ad92: JMP $1600 ИЗ ПРЕРЫВАНИЯ, ISR не возвращается,
управление мотором встаёт. Это инжектор кода для СТОЯЩЕГО блока (заводское
перепрограммирование), а НЕ тап для стрима на ходу. Как живой логгер — отпадает.


================================================================================
ЧАСТЬ 2. ВЫБРАННЫЙ ПУТЬ — СВОЙ ПАТЧ ПРОШИВКИ + SCI-ТЕЛЕМЕТРИЯ
================================================================================
Тот же передатчик SCI, но телеметрию пишем сами: в главный ISR раз в цикл
кладём выбранные переменные в регистр передачи SCI. На выходе — 2-3 провода
(TxD + масса, RxD по желанию), живой поток на ходу, без снифферинга и Pico.
Цена — прошить модифицированный EPROM (это и так умеем через редактор).


ФАКТЫ, НА КОТОРЫХ СТОИТ ПЛАН (проверено по бинарю J30_редактирование.bin)
------------------------------------------------------------------------
1) КУДА ВРЕЗАТЬСЯ — ISR готов.
   Вектор IRQ1 $FFF8 = 0x82E6. Наш периодический обработчик (83e5, цепочка
   JSR 99de / 99f3 / 9b24 / 9bbe / a99b / ad88 ...) лежит внутри него.
   Это главное прерывание по опорному сигналу — крутится на ходу каждый импульс.
   Внутри ISR есть 83eb: CLI (прерывания уже вложены) — цикл не сверхжёсткий.

2) SCI НА ХОДУ СВОБОДЕН.
   Регистры $0010-$0013 трогает ТОЛЬКО загрузчик. Пока $40.7=0 (а на ходу он
   всегда 0) — SCI ничей: ни Consult, ни диагностики. Инициализацию передатчика
   делаем сами. Значения — из проверенного кода загрузчика (ae8b..ae91):
        RMCR  $0010 = 0x0C    ; скорость E/16 = кварц/64
        TRCSR $0011 |= 0x02   ; TE (ТОЛЬКО передача; RE/RIE НЕ трогаем,
                              ;     чтобы не будить RX-загрузчик)
        передача: STAA $0013  ; байт в TDR, предварительно опросив TDRE
        TDRE = бит 0x20 в TRCSR $0011

3) СВОБОДНОЕ МЕСТО В ПЗУ — с запасом.
   Прогон байта 0x3F длиной 10524: cpu C5E4..EEFF (явный padding, не таблица).
   Запасные блоки 0xFF: F4BE..F60F (338), F7FC..F8FF (260).
   Подпрограмму кладём в начало большого блоба, напр. cpu C600.

   (file offset = cpu - 0x8000)

4) КАРТА ВЕКТОРОВ (для справки, из бинаря):
        FFF0 SCI   = ADAA   (RX-обработчик загрузчика)
        FFF2 TOF   = C30E
        FFF4 OCF   = C5D2   (заглушка)
        FFF6 ICF   = 843D
        FFF8 IRQ1  = 82E6   <- наш периодический ISR
        FFFC NMI   = C5DD
        FFFE RESET = AE17


КАК СОБИРАЕТСЯ ПАТЧ
-------------------
ШАГ A. Подпрограмма-телеметрия (в свободном ПЗУ, напр. C600):
   - Проверить TDRE: TIM #0x20,$0011. НЕ готов -> сразу выход.
     (В ISR busy-wait по TDRE ЗАПРЕЩЁН — это опорное прерывание, повесим
      угол/впрыск. Только «готов-шлём / не готов-пропускаем».)
   - Готов -> выдать ОДИН байт round-robin: [синхро 0xFF][RPM hi $140A]
     [RPM lo $140B][нагрузка $1482][Tp $1413]... по байту за вызов.
   - Первый вызов — лениво инициализировать SCI (RMCR + TE) по флажку
     в свободном байте внутреннего ОЗУ.
   - RTS.

ШАГ B. Врезка в ISR — минимум, 3 байта:
   Берём одну существующую JSR в цепочке (напр. 83f8: JSR a99b), меняем
   ОПЕРАНД на адрес нашей подпрограммы (C600). Подпрограмма делает
   JSR a99b (родной вызов) -> телеметрию -> RTS. Прозрачно, логику не ломаем.

ШАГ C. ПК-приёмник:
   USB-serial на TTL 0-5В (НЕ RS232!) прямо на ноги. Ловит синхро 0xFF,
   раскладывает поток по переменным -> проекция на дамп.


ПЕРЕМЕННЫЕ-КАНДИДАТЫ ДЛЯ ЛОГА (все во внешнем ОЗУ HD63140, видны/читаемы)
-----------------------------------------------------------------------
   $140A/$140B  RPM (16-бит)
   $1482        нагрузка (сглаж. расход)
   $1413        Tp (базовая длит. впрыска)
   $1411        итоговый импульс впрыска
   $1437        ALPHA (коррекция замкнутого цикла)
   $1400        O2 (сырой отсчёт АЦП)
   температура, напряжение — уточнить адреса при реализации
   ВНИМАНИЕ: $004x/$008x (duty, напряжение) — ВНУТРЕННЕЕ ОЗУ 6303, для логгера
   читаются кодом штатно, но на внешней шине их НЕТ (для справки).

ЧАСТЬ 6. ПОДТВЕРЖДЁННОЕ ЖЕЛЕЗО + ФАКТЫ (29.07.26)

--- СКОРОСТЬ SCI = 125000 бод (подтверждено даташитом) ---
  Кварц по маркировке = 15986 -> ~15.986 МГц. Даташит HD6303Y: для «B»-грейда
  cycle time min = 0.5 мкс -> шинный клок E = 2 МГц МАКС. Значит E = 2 МГц
  (кварц эффективно /8; выше «B» не может). RMCR=0x0C, биты SS=00 -> baud = E/16
  = 2 000 000/16 = 125 000 (точно 15 986 000/128 = 124 891).
  ВАЖНО: прежнее «кварц/64» в старых частях — НЕВЕРНО (было по ошибочному /4).
  FT232RL: 3МГц/24 = 125000 ровно, расхождение 0.09% -> идеально.
  СТАВИТЬ НА ПК: --baud 125000.

--- ФИЗНОГИ (даташит, корпус YCP; стр.127 pin arrangement, стр.128 block diag) ---
  P24 = Tx (TxD) = НОГА 14   <- сигнал лога
  P23 = Rx (RxD) = НОГА 13
  Масса — любой Vss. Номера ЗАВИСЯТ от корпуса: у обычного YP DIP TxD=нога13,
  у нашего YCP TxD=нога14. Даташит локально: webfetch PDF в tool-results.

--- ОБВЯЗКА НА ПЛАТЕ ---
  TxD (пин14): pull-down 10к (SMD «103») + ESD-диод (SMD «L7», вероятно
  ESD7M5.0 — шунт-клампер на массу) на линии к разъёму. Сигнал доходит до
  разъёма, но паяться НАДЁЖНЕЕ к пину14/пятаку pull-down (сырой сигнал до
  защиты). RxD (пин13) — через 52-ногую кастомную LSI Nissan («A19-257», гейт-
  массив/диаг.фронт-энд); нам не нужен (лог только TX).
  Подключение лога: пин14 -> RXD FT232RL(5В), масса блока -> GND FT232RL.
  НЕ подключать 5В платы к блоку. Ноут на батарее (без петли по земле).

--- КОНТРОЛЬНАЯ СУММА ПЗУ (важно для ЛЮБОГО патча) ---
  Байты 0x7F7A (SUM) / 0x7F7B (XOR) = сумма и XOR всех байт кроме них самих.
  После любого патча ОБЯЗАТЕЛЬНО пересчитать (иначе редактор «✗ не сходится» и
  возможная ошибка блока). Встроено в build_ramdump_patch ИИ.py.

--- БОЕВОЙ БИН ---
  j30/J30_логгер-дамп 29.07.26 ИИ.bin = AKPP-тюн (J30_лучший вариант+акпп...) +
  патч-дампер + пересчитанная сумма (0xE9/0xB1). Проверен на двойнике: дамп
  1216/1216, сумма сходится. Билдер берёт пути аргументами:
  python3 "j30/build_ramdump_patch ИИ.py" <src.bin> <dst.bin>

--- ДАМПЕР ТЕПЕРЬ ДВА ДИАПАЗОНА ---
  Внутр. ОЗУ 6303 $0040-$00FF (192б, там напряжение $008F, темп $00B1, впрыск
  $004D) + внешн. ОЗУ HD63140 $1400-$17FF (1024б). Итого 1216 байт/проход.
  Свои байты состояния $FA-$FD тоже в дампе (значения «живые»).

--- RxD / DALLAS-путь (на будущее, НЕ сейчас) ---
  Через RxD (пин13): peek/poke ОЗУ + управление дампом = интерактивный отладчик.
  Полный live-тюнинг карт = заменить EPROM на Dallas nvSRAM (DS1230) + провод
  /WR проца -> /WE далласа (гейтить логикой/CPLD только на область калибровок) +
  пересчёт суммы. Карты в ПЗУ поком не меняются — нужен перенос в RAM. См.
  память [[j30-nistune-realtime-consult]].
